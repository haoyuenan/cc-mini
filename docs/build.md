# Build and Rebuild Guide

This guide explains how to work with `cc-mini` after source changes, how to regenerate the Windows launcher (`cc-mini.exe`), and how to build distributable packages.

## What `cc-mini.exe` Actually Is

On Windows, `cc-mini.exe` is **not** a separately compiled native application in this repository.

It is a **console launcher generated by `pip`** from the entry point declared in `pyproject.toml`:

- package name: `cc-mini`
- script entry point: `cc-mini = "core.main:main"`

That means:

- changing most Python source files under `src/core/` does **not** require a native rebuild
- in an editable install, code changes are picked up directly from source
- reinstalling the package regenerates the launcher if needed
- `python -m build` creates Python packages (`.whl` and `.tar.gz`), not a standalone single-file exe

## Requirements

- Python 3.11+
- `pip`
- `venv`
- `git`

## Recommended Development Setup

### Windows (PowerShell)

```powershell
Set-Location D:\Work\Projects\cc-mini
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

### macOS / Linux

```bash
cd /path/to/cc-mini
python3.11 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -e ".[dev]"
```

## After Updating Source Code

### Case 1: You only changed Python source files

Examples:

- `src/core/main.py`
- `src/core/engine.py`
- `src/core/tools/...`
- tests or docs

If `cc-mini` was installed with `pip install -e .` or `pip install -e ".[dev]"`, you usually do **not** need to rebuild anything.

Just run it again:

```powershell
.\.venv\Scripts\cc-mini.exe
```

Editable install means the environment points at your working tree directly.

### Case 2: You changed packaging or install metadata

Reinstall when you change:

- `pyproject.toml`
- dependency lists
- script entry points
- package layout
- the virtual environment itself

In that case, reinstall the package:

```powershell
Set-Location D:\Work\Projects\cc-mini
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

If you want to force regeneration of the Windows launcher, uninstall first and then reinstall:

```powershell
Set-Location D:\Work\Projects\cc-mini
.\.venv\Scripts\python.exe -m pip uninstall -y cc-mini
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

This recreates `\.venv\Scripts\cc-mini.exe`.

## Rebuilding `cc-mini.exe` on Windows

If your source has changed and you specifically want to ensure the launcher is fresh, use this workflow.

### Fast path

Use this when:

- the launcher already exists
- you only want to refresh installation metadata
- you changed `pyproject.toml` or dependencies

```powershell
Set-Location D:\Work\Projects\cc-mini
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\cc-mini.exe --help
```

### Clean rebuild path

Use this when:

- you suspect the launcher is stale
- the wrong `cc-mini.exe` is being picked up from `PATH`
- you recreated or copied the environment

```powershell
Set-Location D:\Work\Projects\cc-mini
Remove-Item .\.venv\Scripts\cc-mini.exe -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe -m pip uninstall -y cc-mini
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\cc-mini.exe --help
```

### Check which executable is actually being used

If multiple `cc-mini` launchers exist on your machine:

```powershell
Get-Command cc-mini -All
```

If needed, call the intended launcher directly:

```powershell
.\.venv\Scripts\cc-mini.exe
```

## Building Distributable Packages

To build installable Python artifacts:

```powershell
Set-Location D:\Work\Projects\cc-mini
.\.venv\Scripts\python.exe -m pip install build
.\.venv\Scripts\python.exe -m build
```

This creates:

- `dist/cc_mini-<version>-py3-none-any.whl`
- `dist/cc_mini-<version>.tar.gz`

Verified in this repository on Windows:

- `python -m build` succeeds
- output artifacts are written to `dist/`

## Installing From a Built Wheel

Use this when you want to test the built package instead of an editable install.

### Windows

```powershell
Set-Location D:\Work\Projects\cc-mini
py -3.11 -m venv .venv-wheel-test
.\.venv-wheel-test\Scripts\python.exe -m pip install --upgrade pip
.\.venv-wheel-test\Scripts\python.exe -m pip install .\dist\cc_mini-0.1.0-py3-none-any.whl
.\.venv-wheel-test\Scripts\cc-mini.exe --help
```

### macOS / Linux

```bash
cd /path/to/cc-mini
python3.11 -m venv .venv-wheel-test
./.venv-wheel-test/bin/python -m pip install --upgrade pip
./.venv-wheel-test/bin/python -m pip install ./dist/cc_mini-0.1.0-py3-none-any.whl
./.venv-wheel-test/bin/cc-mini --help
```

Replace the filename if the version changes.

## Verification Checklist

### Basic smoke checks

After rebuilding or reinstalling, verify the launcher and packaging flow first:

```powershell
Set-Location D:\Work\Projects\cc-mini
.\.venv\Scripts\cc-mini.exe --help
.\.venv\Scripts\python.exe -m build
```

### Optional test suite

Then run the test suite if you want broader regression coverage:

```powershell
Set-Location D:\Work\Projects\cc-mini
.\.venv\Scripts\python.exe -m pytest tests -v -k "not integration"
```

Notes:

- In this repository, the build-related smoke checks above were verified on Windows.
- A Windows run of `pytest tests -v -k "not integration"` currently reports some existing failures unrelated to packaging, including local configuration leakage from `.env`, shell-command differences, and path-separator expectations.
- Treat the test suite as a useful regression signal, but do not interpret every current Windows failure as a broken build pipeline.

## Troubleshooting

### `cc-mini.exe` launches old behavior

Possible causes:

- you are running a different launcher from `PATH`
- the package was installed in another virtual environment
- you changed packaging metadata but did not reinstall

Try:

```powershell
Get-Command cc-mini -All
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

### Works in VS Code terminal, fails in external PowerShell

Check for conflicting environment variables:

- `CC_MINI_PROVIDER`
- `CC_MINI_MODEL`
- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`
- `ANTHROPIC_API_KEY`
- `ANTHROPIC_BASE_URL`

Global environment variables can override project-local `.env` values.

### `python -m build` works, but no standalone exe appears

That is expected.

This repository currently builds:

- wheel packages (`.whl`)
- source distributions (`.tar.gz`)

It does **not** include a configured PyInstaller / Nuitka / cx_Freeze pipeline for a standalone native executable.

## Summary

- For normal source edits in an editable install, **no rebuild is usually required**.
- To refresh the Windows launcher, **reinstall the package**.
- To create distributable artifacts, run **`python -m build`**.
- To validate the result, run **`cc-mini --help`** and the test suite.
